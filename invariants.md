# Standing Invariants

These are standing, enforced rules — not historical notes. Each was decided once, deliberately, and logged as an Accepted ADR in `reports/docs/architecture/system_design.md`. They are restated here as the load-bearing philosophy of the project: **every other rule in this document is downstream of them.** If a proposed change conflicts with one of these, the change is wrong, not the invariant. A change to an invariant itself requires a new ADR entry that explicitly supersedes the old one — never a silent edit.

| #      | Invariant                                                                                                                                                                                                                                         | Governing ADR                                       |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| INV-1  | The deterministic core (Tier 1 model, Tier 2 Monte Carlo engine) MUST NEVER accept LLM-generated output as an input to a calculation. No exception is "helpful enough" to justify this.                                                           | ADR-001                                             |
| INV-2  | All inter-tier and inter-agent data exchange MUST flow through the single, versioned Pydantic evidence-bundle schema. No tier or agent may inject ad hoc context outside that contract.                                                           | ADR-002                                             |
| INV-3  | No model version may be promoted to serving unless it passes **both** a discrimination check (AUC/KS) **and** a calibration check (Brier score / reliability curve). Strong AUC alone is never sufficient grounds for promotion.                  | ADR-003                                             |
| INV-4  | Cross-persona divergence MUST be measured by a deterministic function over structured `PersonaVerdict` fields (`recommendation`, `lean`, `confidence`) — never by an LLM judge scoring narrative similarity.                                      | ADR-004                                             |
| INV-5  | All persona nodes MUST run at the same low, uniform temperature. Temperature MUST NEVER be used as a mechanism to manufacture divergence. Divergence is engineered exclusively through role-conditioned rubrics and role-specific derived fields. | ADR-005                                             |
| INV-6  | Every LLM call MUST route through the LLM gateway's circuit breaker. Direct, ungated calls to a provider SDK anywhere in the codebase are prohibited.                                                                                             | ADR-006                                             |
| INV-7  | No model training run may proceed if the Great Expectations data-contract check fails. This gate MUST NOT be bypassed, silenced, or soft-disabled for development convenience.                                                                    | ADR-007                                             |
| INV-8  | Persona roles MUST remain the domain-native CRO / Growth / Capital framing. They MUST NOT be renamed, relabeled, or genericized to match another portfolio project.                                                                               | ADR-008                                             |
| INV-9  | Any file whose divergence score exceeds the documented threshold, or whose Tier 1 confidence falls below the documented threshold, MUST be routed to human-in-the-loop review. The system MUST NEVER auto-resolve such a case silently.           | PRD FR8                                             |
| INV-10 | The system MUST NEVER auto-approve a loan. Its output is always a recommendation for a human decision-maker, regardless of confidence score.                                                                                                      | Scoping Doc §4 (End State), §9 (Constraints) |
